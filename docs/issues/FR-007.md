# [FR-007] Storage, Validation, and Submission Integrity

## Labels
`MUS`, `enhancement`, `platform`

## User Story
As the host, I want uploads and records to be validated consistently, so that the gallery stays performant and the data remains manageable.

## Proposed Solution

### Overview
Establish the backend contracts that protect the system: file validation, direct upload orchestration, and contribution record integrity.

### Implementation Flow
1. Validate incoming submission intent before upload.
2. Issue signed upload details for permitted media.
3. Persist contribution metadata only after the upload contract succeeds.

### Technical Approach

```ts
type ContributionRecord = {
  id: string
  type: 'text' | 'photo' | 'video'
  submitterName: string
  message?: string
  caption?: string
  assetPath?: string
  assetMimeType?: string
  assetSizeBytes?: number
  videoDurationSeconds?: number
}
```

### Key Considerations
- Validation should match public UX and backend enforcement.
- The storage structure should stay simple enough for one developer to reason about.
- Media records and files must not drift out of sync.

## Acceptance Criteria

- [x] Text submissions cannot be created without required fields. ✅
- [x] Photo and video uploads are rejected when file type or size rules fail. ✅
- [x] Video submissions are rejected when duration exceeds 90 seconds. ✅
